# AGENTS: Project Wisp

Обязательные инженерные инварианты для всех задач приложения. Инструкции ролей дополняют этот файл, не дублируют и не ослабляют его.

## 1. Автономность и платформа

- Автономный desktop-клиент: Electron + React + TypeScript, собственный FSM персонажа в `src/domain/character/`, отображение через Renderer/PixiJS.
- Offline-first: вычисления и данные локальны (SQLite/config files). Серверы, внешние БД и микросервисы исключены; единственное сетевое исключение — прямой LLM-вызов через `IAIProvider` из Main.
- Базовая платформа — Linux (Ubuntu, Wayland/X11); целевые — Windows/macOS. Файловые пути собирать через `path.join`; соблюдать точный регистр файлов и импортов.
- ОС-специфика и `process.platform` — исключительно в `src/infrastructure/platform/` за `IPlatformAdapter`.

## 2. Архитектура и контракты

| Слой | Владеет | Граница |
|---|---|---|
| Domain | Бизнес-логика, Needs/Mood, FSM, кинематика, правила анимации | Чистый детерминированный TS; без React/DOM, Electron, Node.js, SQLite, AI SDK. Время, RNG, события — явные входы; без системных таймеров, `Date.now()` и `Math.random()`. |
| Application | Use cases, команды/запросы, оркестрация, порты | Платформенно-нейтрален, без UI/SQL и семантических решений за Domain. Порт объявляет потребитель в `src/application/ports/`. |
| Infrastructure | Реализации портов | Инкапсулирует Electron, ОС, файловую систему, SQLite, AI-провайдеры. |
| Main | Окна, IPC handlers, DI, оркестрация use cases | Единственный владелец внешних сетевых вызовов. |
| Renderer | Presentation и пользовательский ввод | Не владеет бизнес-логикой, FSM или физикой. |

- **Contracts-first:** объявить/обновить порты в `src/application/ports/` и DTO в `src/shared/ipc-contracts.ts` **до** реализации сервисов/адаптеров.
- `IAIProvider` возвращает семантический DTO, не знает React/DOM, стили и кадры. Render владеет visual props/слоями/геометрией, Animation — клипами/приоритетами/прерываниями.
- Правила движка — в его канонической [спецификации](docs/engine/README.md), формы типов — в коде. При конфликте не выбирать удобную версию: остановить затронутую часть и запросить `architect`.

## 3. Безопасность Electron и IPC

- Все `BrowserWindow`: `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`.
- Renderer обращается к Main только через typed `window.wispAPI` из `src/preload/`; прямые `ipcRenderer.send/invoke` со строковыми каналами запрещены.
- Main валидирует все входы IPC до обработки. Renderer не выполняет сетевых запросов и не получает Node.js/persistence/provider internals.

## 4. UI и производительность

React отображает presentation state и передаёт действия в IPC. Избегать лишних ререндеров; анимации — `requestAnimationFrame`/CSS transforms (`translate3d`). Перемещение окна — IPC-батчами, без частых попиксельных синхронных вызовов.

## 5. Зависимости

Zero New Dependencies First / YAGNI. До новой npm-зависимости `architect` проверяет: пермиссивную лицензию (MIT/Apache-2.0/BSD/ISC); размер и transitives; maintenance за последний год и отсутствие открытых critical CVE; предпочтение pure JS/WASM вместо native/node-gyp; возможность заменить пакет 50–100 строками своего TS.

## 6. TypeScript и код

Strict mode; запрет `any`, двойных приведений `as unknown as T`, `@ts-ignore`. Использовать `unknown` с guards; `@ts-expect-error` — только с причиной. IPC/события/сущности строго типизированы, свойства `readonly` по умолчанию. Явные имена, без мёртвого кода/неиспользуемых импортов; ориентир — до 300 строк реализации на файл.

## 7. Тестирование и рефакторинг

Багфикс начинается с воспроизведения и падающего регрессионного теста. Рефакторинг сохраняет поведение, опирается на тесты и не смешивается с фичами. Unit-тесты мокают внешние адаптеры; таймеры — через Vitest fake timers.

## 8. Scope и спрайты

- Продуктовые изменения — только `src/`, `public/`, `tests/`, `docs/`, в пределах полномочий назначенной роли. Инструкции (`AGENTS.md`, `.agents/**/*.md`) и корневую навигацию меняет `project-manager` в своей документационной задаче либо исполнитель по прямому поручению пользователя изменить эти документы. Разработчик, архитектор и ревьюер не правят правила ради обхода ограничений своей задачи; tooling/config этим исключением не разрешены.
- `asset-pipeline/` и `discord_orcestrations/` — отдельные внешние скоупы: продуктовым ролям запрещены изменения и запуск их скриптов. Продуктовый diff в них отклоняется. Не откатывать чужие изменения.
- Графику создаёт только внешний художник-человек вне ИИ-системы. Агентам запрещено рисовать, генерировать, нарезать спрайты или ставить такие задачи другим агентам.
- Готовые ассеты — только `public/assets/sprites/`, манифест — `public/assets/sprites/manifest.json`. Если ассета нет: fallback/заглушка/алиас в коде + запись в [SPRITE_REQUESTS](docs/art/SPRITE_REQUESTS.md): Task ID, ключ, fallback, требования к кадрам/движению. Ключи указать в `SPRITES` отчёта.

## 9. Роли агентов

Читать только назначенную роль. «Менеджер» означает `project-manager`. Если роль не назначена, выполнять запрос пользователя в его scope, не загружая инструкции всех ролей. Отсутствие роли не отменяет общие границы и проверки; агент не присваивает себе полномочия остальных ролей.

| Роль | Ответственность |
|---|---|
| [project-manager](.agents/agents/project-manager/agent.md) | Scope, GitHub backlog, маршрутизация, спринты и парные промпты; без продуктового кода. |
| [architect](.agents/agents/architect/agent.md) | Архитектура, инварианты, порты/DTO в коде, Dependency Review; без реализации. |
| [app-developer](.agents/agents/app-developer/agent.md) | Vertical slice во всех слоях: порты/DTO на Fast-Track, реализация и тесты. |
| [reviewer](.agents/agents/reviewer/agent.md) | Независимый аудит diff и verification; точечный Fast-Fix типов/тестов. |

Fast-Track → `app-developer` по умолчанию. `architect` обязателен по любому из четырёх триггеров:

1. Новая подсистема/технология: новый модуль в `src/domain/`, новая спецификация движка в `docs/engine/`, интеграция нового движка (включая persistence или реального AI-провайдера вместо mock).
2. Сдвиг межслойных/процессных границ, изменение правил изоляции/безопасности или принципиально новые IPC-паттерны.
3. Новая внешняя npm-зависимость.
4. Явный запрос пользователя, `needs:architect`, архитектурный тупик или конфликт контрактов.

Эволюционное расширение портов/DTO в существующих границах — Fast-Track. Наличие этих каталогов в разрешённом scope не позволяет обходить architect gate.

## 10. Цикл задачи

`implementation/fixes ↔ review` идёт без промежуточного менеджера; он подключается после `Approved`/`done`. Статусы GitHub Project и закрытие Issues — только менеджер. Одна роль и подсистема — продолжать текущий чат; смена роли/подсистемы или перегруженный контекст — новый чат.

## 11. План, верификация и отчёт

Перед правками определить файлы и короткий план. Делать минимальный законченный vertical slice, использовать существующие абстракции, не менять unrelated files.

| Изменение / роль | Обязательная финальная проверка |
|---|---|
| Реализация / app-developer | `npm run typecheck` и затем `npm test` |
| Архитектор: порты/DTO в коде | `npm run typecheck`; ссылки и лимит спецификаций |
| Независимое review любой задачи, включая docs-only | `npm run typecheck` и аудит diff; для docs также ссылки/согласованность. `npm test` запрещён, в том числе после Fast-Fix |
| Docs-only исполнение, включая менеджера | Ссылки, согласованность правил и чистота diff; продуктовые тесты не нужны. Независимый reviewer выполняет строку выше. |

`npm run build` запрещён для всех задач. Использовать только существующие скрипты `package.json`. Сначала затронутые/ранее упавшие тесты; финальный gate по таблице. Успешные проверки повторять только после влияющих на результат изменений. После обязательной проверки scope не расширять.

Отчёт: `TASK` (ID/scope) → `CHANGES` → `BOUNDARIES` → `SPRITES` (ключи из реестра или `none`) → `VERIFICATION` (результат либо `NOT RUN` с причиной) → `RECOMMENDED NEXT GATE` (`reviewer`/`architect`/`blocked`/`done`). Без хронологии и полных логов.

## 12. Экономия контекста и документация

- Стартовый контекст: этот файл (если уже передан — не перечитывать), назначенная роль, текущая Issue/запрос. [Навигатор](docs/README.md) нужен только для поиска источника.
- Сначала `rg --files`/`rg -n`, затем релевантные фрагменты. Для затронутого контракта читать владение/границы и изменяемые правила; при изменении обмена — обе стороны. Расширять чтение при неясности, не угадывать инварианты ради экономии.
- Не загружать всё `docs/`, чужие роли, историю отчётов или `ARCHITECTURE.md` по умолчанию. Связанный architect result и его Implementation consequences обязательны; справочные ссылки не являются командой прочитать всё.
- Не перечитывать неизменённые источники/результаты, уже доступные в контексте. Логи возвращать как exit code, итог и уникальную диагностику; массовый сбой объяснять общей причиной.
- Спецификации: концепции, инварианты, формулы, FSM-матрицы, компактные таблицы и ссылки на типы. Максимум 450 строк, **без минимального объёма**; не раздувать до 250–400 строк. Не копировать типы/псевдокод, общие правила или историю проверок. Изменять каноническое правило вместо дописывания его очередного пересказа.
