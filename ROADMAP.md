## 📋 Детальное описание фаз

---

### Phase 0 — Repository / Architecture Setup
- **Цель:** Подготовить инфраструктуру документации, архитектурные правила, платформенные контракты и инструментарий для AI-агентов.
- **Ожидаемый результат:** Готовые `AGENTS.md`, `ARCHITECTURE.md`, `ROADMAP.md` и директория `.agents/` со всеми правилами, воркфлоу, кроссплатформенными требованиями и скиллами.
- **Что входит:**
  - Описание архитектуры, IPC-модели, процессов Electron, кроссплатформенных адаптеров.
  - Формирование правил для TypeScript, React, Electron Security, Testing, Cross-Platform.
  - Определение конфигураций специализированных агентов.
- **Что НЕ входит:**
  - Написание кода приложения, установка новых зависимостей, бэкенд.
- **Критерии готовности:**
  - [x] Все файлы созданы на русском языке (структура путей на английском).
  - [x] Архитектура полностью согласована, учтены Linux (Ubuntu), Windows и macOS.

---

### Phase 1 — Electron Shell
- **Цель:** Создать минимальный работающий каркас приложения на Electron + Vite + React + TypeScript с поддержкой HMR.
- **Ожидаемый результат:** Запускающееся окно приложения с работающим typed IPC и строгой изоляцией процессов на Ubuntu Linux (и совместимо с Win/Mac).
- **Что входит:**
  - Конфигурация TypeScript для Main, Preload и Renderer.
  - Базовый `main.ts` с созданием `BrowserWindow`.
  - Минимальный `preload.ts` с вызовом `contextBridge.exposeInMainWorld`.
  - Точка входа React в Renderer.
  - Скрипты сборки и запуска (`npm run dev`, `npm run build`), проверенные на Linux.
- **Что НЕ входит:**
  - Прозрачность, анимации персонажа, чат, базы данных.
- **Критерии готовности:**
  - Приложение успешно запускается локально в Ubuntu Linux (`npm run dev`).
  - В консоли нет ошибок безопасности (`contextIsolation: true`, `nodeIntegration: false`).

---

### Phase 2 — Transparent Desktop Pet
- **Цель:** Превратить окно Electron в прозрачный поверх-всех-окон (always-on-top, frameless) оверлей рабочего стола с использованием кроссплатформенного адаптера окон.
- **Ожидаемый результат:** Окно не имеет системной рамки, прозрачный фон, остаётся поверх остальных окон, корректно обрабатывает прокликивание (click-through) пустых областей в среде Ubuntu Linux (с поддержкой X11 и Wayland).
- **Что входит:**
  - Выделение интерфейса `IPlatformAdapter` и реализация `LinuxPlatformAdapter`.
  - Настройка флагов окна: `transparent: true`, `frame: false`, `alwaysOnTop: true`, `hasShadow: false`, `skipTaskbar: true`.
  - Управление `setIgnoreMouseEvents` при наведении на прозрачные области.
- **Что НЕ входит:**
  - Сложная физика, диалоги, AI.
- **Критерии готовности:**
  - Персонаж виден на рабочем столе на прозрачном фоне в Ubuntu.
  - Клики сквозь прозрачные зоны попадают в приложения под оверлеем.

---

### Phase 3 — Dragging and Positioning
- **Цель:** Реализовать возможность захвата и перемещения персонажа мышью с контролем границ экрана для любой ОС.
- **Ожидаемый результат:** Пользователь может перетаскивать персонажа; персонаж сохраняет координаты и не улетает за пределы видимой рабочей области монитора (с учётом GNOME Dock/TopBar, панели задач Windows или macOS Dock).
- **Что входит:**
  - Обработка `mousedown`/`mousemove`/`mouseup` или нативный drag IPC.
  - Определение границ текущего дисплея через платформонезависимый адаптер (`screen.getDisplayNearestPoint`).
  - Сохранение последней позиции в памяти процесса.
- **Что НЕ входит:**
  - Сохранение в базу данных (пока только in-memory).
- **Критерии готовности:**
  - Плавный drag-and-drop без подёргиваний и отставаний.
  - Персонаж упирается в границы экрана с учётом системных панелей.

---

### Phase 4 — Character Rendering
- **Цель:** Создать компонент отрисовки визуального образа персонажа (спрайты/SVG/Canvas).
- **Ожидаемый результат:** Персонаж отображается в заданном масштабе с чёткими пикселями/линиями без размытия при различном DPI дисплеев.
- **Что входит:**
  - Компонент `CharacterView` в React.
  - Загрузка базового набора статических спрайтов (idle, walk, grab).
  - Поддержка отзеркаливания по горизонтали (`direction: left | right`).
- **Что НЕ входит:**
  - Автоматические переходы стейт-машины, диалоги.
- **Критерии готовности:**
  - Спрайт корректно масштабируется без артефактов на High-DPI экранах.

---

### Phase 5 — Animation State Machine
- **Цель:** Разработать изолированную стейт-машину анимаций персонажа.
- **Ожидаемый результат:** Плавная смена анимационных циклов (Idle → Walk → Dragged → Fall → Land) с контролем кадров и прерываемости.
- **Что входит:**
  - Pure TypeScript `AnimationController` и `AnimationStateMachine` (100% OS-neutral).
  - Поддержка зацикленных и одиночных анимаций с callback завершения.
  - Приоритеты анимаций (прерывание фоновой анимации при начале перетаскивания).
- **Что НЕ входит:**
  - AI, генерация реплик.
- **Критерии готовности:**
  - Unit-тесты покрывают переходы всех состояний.
  - Визуальная смена анимаций работает без глитчей.

---

### Phase 6 — Basic Character Behavior
- **Цель:** Добавить персонажу автономность и «жизнь» на рабочем столе.
- **Ожидаемый результат:** Персонаж самостоятельно решает погулять, посидеть, осмотреться или вздремнуть, если пользователь его не трогает.
- **Что входит:**
  - `BehaviorStateMachine` в Domain/Application слое.
  - Таймеры случайных автономных действий с учётом текущего настроения и уровня энергии.
  - Простая симуляция физики (падение вниз до нижнего края экрана, если отпустили в воздухе).
- **Что НЕ входит:**
  - Чат и языковая модель.
- **Критерии готовности:**
  - Персонаж автономно двигается и меняет состояния при бездействии пользователя.

---

### Phase 7 — Interaction
- **Цель:** Реализовать систему интерактивного взаимодействия пользователя с компаньоном.
- **Ожидаемый результат:** Персонаж реагирует на клики (радуется, пугается), двойной клик открывает диалог, правый клик открывает контекстное меню.
- **Что входит:**
  - Обработчики кликов, поглаживания (hover), двойного клика.
  - Кастомное контекстное меню (выход, открыть чат, настройки, сменить настроение).
- **Что НЕ входит:**
  - Генерация ответов через LLM.
- **Критерии готовности:**
  - Контекстное меню стабильно открывается и выполняет команды.

---

### Phase 8 — Local Chat UI
- **Цель:** Создать визуальный интерфейс для общения с персонажем.
- **Ожидаемый результат:** Всплывающий речевой пузырь (speech bubble) и окно ввода сообщения рядом с персонажем.
- **Что входит:**
  - Компоненты `SpeechBubble`, `ChatWindow`, `MessageList`, `ChatInput`.
  - Анимация появления/скрытия речевого пузыря.
  - Автоматическое позиционирование окна чата относительно персонажа, чтобы не вылезать за экран.
- **Что НЕ входит:**
  - Реальный AI-бэкенд (подключается заглушка на следующем шаге).
- **Критерии готовности:**
  - Пользователь может ввести текст и увидеть эхо/заглушку в списке сообщений.

---

### Phase 9 — MockAIProvider
- **Цель:** Внедрить абстракцию `IAIProvider` и полноценный локальный офлайн-провайдер `MockAIProvider`.
- **Ожидаемый результат:** Персонаж осмысленно отвечает на типовые фразы, выражает эмоции в ответах и симулирует процесс размышления.
- **Что входит:**
  - Интерфейсы `IAIProvider`, `AIMessage`, `AIResponse`.
  - Реализация `MockAIProvider` со словарем ответов, ключевыми словами и симуляцией задержки.
  - Отображение статуса «Персонаж думает...» с соответствующей анимацией.
- **Что НЕ входит:**
  - Сетевые запросы, внешние API-ключи.
- **Критерии готовности:**
  - Чат полностью функционален в офлайне без ошибок сети.

---

### Phase 10 — Local Memory (SQLite)
- **Цель:** Реализовать долговременное локальное хранилище данных и памяти персонажа с кроссплатформенными путями.
- **Ожидаемый результат:** История сообщений, выученные факты о пользователе и состояние настроения сохраняются между перезапусками приложения.
- **Что входит:**
  - Подключение `better-sqlite3` в Main-процессе.
  - Разрешение путей к файлу БД через `app.getPath('userData')`.
  - Схема БД: таблицы `settings`, `messages`, `memories`, `character_state`.
  - Репозитории: `SQLiteMemoryRepository`, `SQLiteSettingsRepository`.
  - Базовые миграции схемы (`PRAGMA user_version`).
- **Что НЕ входит:**
  - Облачная синхронизация.
- **Критерии готовности:**
  - После перезапуска приложения история диалога и настройки восстанавливаются.

---

### Phase 11 — Settings
- **Цель:** Разработать пользовательский интерфейс настроек приложения и платформенные адаптеры автозапуска.
- **Ожидаемый результат:** Окно настроек, позволяющее менять масштаб персонажа, звуковые эффекты, поведение (частоту блуждания), тему и автозапуск (нативно для Linux/Win/Mac).
- **Что входит:**
  - Модальное окно `SettingsModal`.
  - Интеграция с `ISettingsRepository`.
  - Реализация адаптера автозапуска через `IPlatformAdapter` (для Linux — `.desktop` файл в `~/.config/autostart`, для Win/Mac — `app.setLoginItemSettings`).
- **Что НЕ входит:**
  - Настройки удалённого аккаунта/профиля.
- **Критерии готовности:**
  - Изменение масштаба мгновенно применяется к персонажу и сохраняется в БД.
  - Переключение флага автозапуска корректно отрабатывает в Linux.

### Phase 12 — Backend Abstraction
- **Цель:** Финализировать и изолировать абстракции перед будущей интеграцией с реальным сервером.
- **Ожидаемый результат:** Полная готовность клиентского кода к переключению на удалённый API через конфигурационный флаг без модификации UI/Domain/Platform адаптеров.
- **Что входит:**
  - Фабрика провайдеров `AIProviderFactory`.
  - Стандартизация сетевых DTO и обработки ошибок сети.
- **Что НЕ входит:**
  - Сам бэкенд на Python.
- **Критерии готовности:**
  - Архитектурный аудит подтверждает нулевую связность UI с реализацией провайдера.
