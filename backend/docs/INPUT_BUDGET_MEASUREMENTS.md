# Оценка входного контекста и резерв ответа

Текущие алгоритмы и ограничения описаны в [Context/Prompt Engine](CONTEXT_PROMPT_ENGINE.md#бюджет-и-ошибка).

OpenAI использует локальную оценку полного итогового payload; она не является
точным подсчётом токенов или гарантией размещения запроса в окне модели.
Gemini использует официальный countTokens в пределах исходного deadline.

Output reserve равен минимуму серверной настройки и лимита сценария и целиком
вычитается из доступного окна: chat до 4096, touch/event/observation до 1024,
summary до 512. Selector не уменьшает этот резерв ради дополнительных данных.
Ответ максимальной разрешённой длины не обязательно помещается в этот резерв.
При length/incomplete JSON частичный ответ не публикуется и автоматического повтора нет.

Проверки алгоритмов оценки, Unicode, границ бюджета и provider lifecycle остаются
локальными unit-тестами с mock transport. Архивы модельных экспериментов,
синтетический корпус и команда сравнения промптов удалены.
