# Риг и анимация чиби-персонажа

Рабочая папка для подготовки персонажа пользователем и ИИ. Исходник —
[character_reference.png](character_reference.png), PNG RGBA, 1024 × 1536.
Копия приложения сохранена без преобразований.

SHA-256: `f0c3a98fc8876b3aebbaf9804db8ccd611c2465c6bca49d0171e7bff7fd13cb7`.

## Выбранный процесс

Предварительный выбор для первой пробы: **исходные пиксели и маски деталей →
PNG-слои с Layout JSON → PSD2Live → редактируемый риг → анимации параметров**.
Это выбор по изученной документации на 2026-10-18, а не результат испытания
инструментов на этом персонаже. Установка и создание рига — следующий этап.

Цель — сохранить узнаваемость лица, волос, одежды и пропорций. Движение задаётся
сетками, деформерами, костями и ключевыми кадрами. Однажды подготовленные текстуры
используются повторно во всех кадрах. MCP даёт ИИ доступ к операциям редактора;
качество определяется подготовкой деталей и проверкой деформаций.

## Инструменты и ограничения

| Инструмент | Назначение | Решение для пробы |
|---|---|---|
| [SAM 2](https://github.com/facebookresearch/sam2) | Сегментация изображения по подсказкам; результат — маски | Кандидат для выделения исходных пикселей. Не восстанавливает скрытые области. Точность на маленьких деталях этого рисунка предстоит проверить. |
| [PSD2Live](https://github.com/tsunehimatoi/psd2live) | Авториг из слоёв, сетки, параметры, физика и редактирование | Основной кандидат. Собственный проект сохраняет возможность правок; экспорт требует проверки в целевом проигрывателе. |
| [See-through](https://github.com/shitagaki-lab/see-through) | Разложение аниме-рисунка на слои с дорисовкой перекрытых частей | Альтернатива для подготовки слоёв. Использует diffusion: может изменить видимые детали, поэтому результат нельзя автоматически принять за точную копию исходника. |
| [Stretchy Studio](https://github.com/MangoLion/stretchystudio) | Визуальный редактор деформируемых слоёв, ориентированный на See-through | Запасной вариант для эксперимента. [Документация экспорта](https://github.com/MangoLion/stretchystudio/blob/master/docs/live2d_export_implementation.md) указывает ограничения прямого MOC3, включая непривязанные повороты/деформации. |
| [Rev2D](https://github.com/RevStudio/Rev2D) | Текстовый риг, CLI/MCP, визуальная проверка и исправления | Запасной инструмент автоматизации. Не поддерживает полноценный MOC3; обмен JSON движений не равен экспорту Live2D-модели. Сам автор позиционирует его как экспериментальный инструмент. |
| [CubismExternalEditMCP](https://github.com/nana7chi/CubismExternalEditMCP) | Управление официальным Cubism Editor | Не первая проба: расширенные операции требуют 5.4 Alpha по README. Версию и доступность API необходимо перепроверить перед установкой. |

У PSD2Live опубликован [релиз v3.5.1](https://github.com/tsunehimatoi/psd2live/releases/tag/v3.5.1)
с пакетами для Windows и Linux. Редактор имеет GPL-3.0; здесь он рассматривается
как отдельный авторский инструмент, а не новая зависимость приложения Wisp.
Наличие релиза не доказывает качество автоматического рига на нашем исходнике.

### Почему PSD2Live подходит для работы с ИИ

- [Layout manifest](https://github.com/tsunehimatoi/psd2live/blob/master/docs/zh/spec/LAYOUT_MANIFEST.md)
  принимает отдельные изображения с координатами, порядком наложения и тегами.
  Photoshop и промежуточный PSD не обязательны.
- [MCP API](https://github.com/tsunehimatoi/psd2live/blob/master/docs/zh/agent/MCP_AUTHORING.md)
  предоставляет операции редактирования, предварительной проверки и истории.
  MCP сам по себе не содержит генератор изображений.
- В [исходнике моста](https://github.com/tsunehimatoi/psd2live/blob/master/mcp_proxy.py)
  есть доступ через Python/CLI к локальному MCP endpoint; это также позволяет
  автоматизировать операции без ручного управления каждым элементом интерфейса.
- [Границы экспорта](https://github.com/tsunehimatoi/psd2live/blob/master/docs/zh/spec/RUNTIME_EXPORT_ARCHITECTURE_AND_GAPS.md)
  различают внутреннее представление, редактирование и результат в другом runtime.
  Сохранение и повторное открытие проекта входят в нашу проверку.

## Подготовка изображения

1. Сохранить оригинал как неизменяемый эталон.
2. Сначала выделить видимые детали масками, сохраняя исходные RGB-пиксели.
   Автоматические маски корректировать по контурам, особенно у глаз и волос.
3. Собрать нейтральную позу из слоёв и сравнить её с оригиналом до рига.
4. Отдельно перечислить недостающие области: лицо под чёлкой, белки за радужками,
   шея под головой, руки под рукавами, перекрытия в суставах.
5. Для этих областей выбрать небольшие локальные дополнения либо ограничить
   амплитуду движения. При использовании генеративной дорисовки фиксировать
   маску изменения и возвращать исходные пиксели вне неё.

See-through — не сегментатор, сохраняющий все пиксели. Его слои могут служить
кандидатами для скрытой геометрии и расположения частей. Принятие результата
зависит от совпадения видимого дизайна. У авторов есть
[официально связанная демонстрация](https://huggingface.co/spaces/24yearsold/see-through-demo);
облачный запуск передаёт изображение внешнему сервису. В рамках подготовки
изображение туда не загружалось.

Полноценный профиль и спина не содержатся в фронтальном PNG. Их потребуется
создать отдельно при расширении набора ракурсов. Зеркалирование меняет стороны
двухцветных волос, заколок и браслетов этого персонажа.

## Первая проба и критерии качества

Первый участок — лицо и небольшой наклон головы, затем тело и ходьба.

| Этап | Что проверять |
|---|---|
| Нейтральная поза | Совпадение с исходником при наложении; сохранены глаза, контур лица, рисунок футболки и асимметрия |
| Взгляд и моргание | Независимые глаза, радужки скрываются веками, закрытый глаз сохраняет форму; нет простого сплющивания всего глаза |
| Наклон и волосы | Небольшой диапазон поворота; без отверстий на перекрытиях и чрезмерного растяжения лица |
| Эмоции | Улыбка, удивление, сонливость через сочетание глаз, бровей и рта |
| Шаги и жесты | Сгибы не разрываются, стопы сохраняют контакт в фазе опоры, обувь и принт не растягиваются чрезмерно |
| Повторное открытие | Проект восстанавливает слои, риг и анимации; экспорт визуально проверяется отдельно |

Проверочная сцена: взгляд в сторону → моргание → улыбка → наклон головы →
два шага → остановка. Проверять как в исходном, так и в реальном экранном размере.
Устойчивый результат на этой сцене предшествует массовому созданию движений.

## Рабочая среда и продолжение

Команды этого этапа выполнялись из `rig_animations/` после создания папки.
Node.js и Python доступны. `nvidia-smi` завершился ошибкой связи с драйвером:
работоспособность локального GPU для See-through/SAM 2 не подтверждена.
Это не доказывает отсутствие видеокарты. Локальный тяжёлый inference пока не запускался.

Следующий шаг — проверить выбранную версию PSD2Live и доступ к её локальному
редактору/MCP, затем подготовить маски лица. Рабочие слои, проекты и предпросмотры
будут храниться внутри этой папки. Сейчас здесь только эталон и описание процесса;
внешние программы, модели и зависимости не установлены.

Подключение нового runtime к Wisp — отдельная архитектурная задача после
оценки качества. Этот эксперимент не изменяет desktop/backend, их зависимости
или существующие правила проекта.
