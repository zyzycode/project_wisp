# Проблемы и новый процесс

## Вывод

Глаза получились: отдельная полная радужка двигается внутри сохранённой формы глаза. Этот подход нельзя механически переносить на всю руку. В r16 изменились рукав, пропорции и характер исходного рисунка; пользователь отверг результат. Успех локального стыка не доказывает качество руки на персонаже.

## Что пошло не так

| Проблема | Где проявилась | Правило следующей попытки |
|---|---|---|
| Неполная исходная радужка обрезалась при вертикальном движении | Ранние gaze; особенно край вниз | Полная отдельно принятая текстура, затем проверка настоящей маски глаза и пределов. |
| Веки начали двигаться до решения зрачков | gaze r05 | Не менять соседние части для компенсации дефекта текущей. |
| Генерация без точного исходного референса меняла глаз | Первая генерация радужек | Оригинал — реальный вход каждого запроса; фактические размеры и alpha проверять. |
| Генерировали анатомию раньше точной исходной сборки | ARM r10–r16 | Сначала выделять видимые исходные пиксели; скрытые места восстанавливать только по необходимости. |
| Неудачный стык кисти | ARM r10/r11; локально исправлен r12 | Проверять силуэт, толщину, направление контуров и перекрытия. |
| Рука слишком тонкая, затем толщину правили без общей опоры | ARM r13/r14 | Сверять длины и ширину с оригиналом на всём персонаже. |
| Прямоугольный артефакт сгиба | ARM r14; локально исправлен r15 | Плавная alpha-граница в скрытом перекрытии; не резать видимый контур прямой маской. |
| Рукав растянут под новую руку; складки и силуэт испорчены | ARM r16 | Не использовать большую неоднородную деформацию как способ подогнать несогласованные слои. |
| Приёмку фрагмента фактически переносили на целое | r12/r15 → r16 | Приёмка позы, текстуры, стыка, рига и клипа — отдельные записи. |
| Скрытая ткань выглядела чужой; старый контроллер руки был плох | ARM r05/r07 | Не продолжать отвергнутую основу. Не компенсировать отсутствие слоя деформером корпуса. |
| Технические проверки выдавались за достаточный результат | Несколько этапов | Save/reopen, валидная сетка и хеши обязательны, но не устанавливают визуальное сходство. |

## Новый порядок для руки

1. Использовать неизменный оригинал и принятую целевую позу только как ориентир движения. Сохранить готовые глаза.
2. Вырезать видимую руку, рукав и браслеты масками исходных пикселей. Слой — техническая граница, а не повод перерисовать деталь. Ранее принятая одежда r04 доступна как материал.
3. Собрать исходную опущенную позу без движения. Сверить RGBA, силуэт, складки, браслеты и контуры на всём персонаже при исходном и экранном масштабе, на светлом и тёмном фоне. Любую погрешность отдельно показать.
4. После приёмки слоёв двигать один сустав в малой амплитуде. Проверить середину, край и возврат. Не тянуть корпус за локтем.
5. Только обнаружив открывшуюся пустоту, определить её маску и добавить недостающую поверхность отдельным слоем. Сохранить исходные видимые пиксели; исходник не перезаписывать.
6. После приёмки малого движения расширять диапазон к целевой позе. Открытая ладонь не извлекается из другого силуэта кисти: это отдельная замена и отдельная приёмка.
7. Сочетания контроллеров, motion и экспорт — следующие этапы, после их явного запуска пользователем.

Если нужна генерация: одна картинка/один слой на запрос, оригинал в качестве фактического входа, отдельно raw PNG и нормализованный PNG, записать prompt, метод, размеры, crop/scale и alpha. Каждый результат смотреть в сборке. Согласование уже данного пользователем объёма не запрашивать повторно. Новая область дорисовки или новый внешний сервис требуют конкретного согласования.

## Технические ловушки

- При частичной alpha нельзя удалять исходный пиксель целиком по условию `mask > 0`: появляются провалы и бахрома. Проверять обратную композицию.
- Проверять прозрачность на составном фоне: RGB под нулевой alpha может выглядеть как призрак в отдельных просмотрщиках.
- Импорт PNG в PSD2Live может обрезать прозрачные поля и центрировать содержимое; bounds сетки не равны исходной регистрации текстуры. Проверять реальные координаты.
- В r04 перестройка split meshes дала неверные UV; рабочая сборка получена свежим Layout из очищенных PNG. `canvas_deform_stroke` в более поздних пробах падал: не повторять без отдельной проверки и сохранённой копии.
- Native-проект должен открываться заново с теми же слоями/ключами. Снимок PNG и диагностический JSON не заменяют `.psd2live`.
- Бинарная маска с жёсткой обратной композицией может сохранить пиксели вне области изменения; она не гарантирует правильную анатомию внутри. ControlNet/pose conditioning тоже не гарантируют геометрию или стиль. Их установка и применение здесь не подтверждены. Не путать GPU редактора с запуском нейросети.
- Исходный порядок браслетов: красный ближе к кисти, синий ближе к локтю. Целевая генерация не является источником истины для таких деталей.

## Сохранённые ограничения

r04: нет скрытой ткани под волосами, нижний край футболки приблизительный. r12/r15: локальные статические фрагменты; нет принятой нейтральной сборки руки на персонаже. Глаза: приняты четыре направления отдельно; моргание, диагонали, клип, экспорт и интеграция не проверены как законченный результат.
