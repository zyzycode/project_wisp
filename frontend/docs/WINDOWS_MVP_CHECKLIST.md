# Windows: ручная проверка персонажа, памяти и ИИ

Ручную приёмку выполняет владелец продукта. Автоматические результаты и закрытые задачи не подтверждают Windows-прогон: фиксировать версию, окружение и результат каждого сценария.

Перед ручной приёмкой выполнить [повторяемый desktop smoke](DESKTOP_SMOKE.md): `node scripts/wisp.mjs smoke:desktop`. Его injected-input проверки не заменяют физический drag, прозрачность композитора и DPI-переходы из ручной матрицы.

## Запуск и доступные режимы

Подготовить окружение по [корневому README](../../README.md#подготовка). Все команды ниже выполняются из корня репозитория.

```powershell
node scripts/wisp.mjs dev
```

Launcher запускает desktop и передаёт доверенный путь локального backend/Python. Без внешнего URL Main запускает личный backend только при наличии сохранённого ключа; без ключа используется локальный Mock. Chat включает память, карточку и appraisal; touch, summary и observation используют тот же префикс. Сетевые инициативы выключены по умолчанию. Фактические возможности и ограничения — в [backend README](../../backend/docs/README.md#поддерживаемые-сценарии).

Личный ключ OpenAI сохраняется в меню «Подключение AI» через защищённое хранилище; сохранение/удаление перезапускает Wisp, но не проверяет ключ запросом. Для локального Mock отключить личное подключение в меню и запускать без `WISP_BACKEND_URL`: одно отсутствие URL не отключает сохранённый ключ. Для отдельного, заранее запущенного backend и сетевых инициатив:

```powershell
$env:WISP_BACKEND_URL = "http://127.0.0.1:8000"
$env:WISP_AI_EVENTS_ENABLED = "true"
node scripts/wisp.mjs dev:frontend
```

Выбора версии API нет. `WISP_AI_EVENTS_ENABLED=false` отключает инициативы, сохраняя память в диалоге. Изменение конфигурации требует перезапуска Main. В режиме внешнего URL LLM-ключ задаётся серверу, личный ключ из меню не используется; управление им в UI недоступно. Удалённый endpoint требует HTTPS base URL без endpoint path/query/credentials и подтверждённых оператором условий доступа и обработки данных. Development loopback не является конфигурацией packaged-клиента.

Сценарии 2–5 проверяют память и сетевые ответы; сценарий 6 требует включённых events. Недоступный сценарий отмечать NOT RUN с причиной.

Проверить dev и отдельно уже предоставленный portable: записать commit, Windows/Electron версии, userData, размер артефакта и версии desktop/backend. Подготовка portable — отдельный packaging scope; `npm run build` запрещён инженерными правилами.

## Сценарии

1. **Локальная жизнь.** Запуск, окно, меню, drag, облачко, игра: поймала/промахнулась/потеряла цель/прервана. После игры возвращается к обычным занятиям. Повторить при остановленном backend: ввод и движение продолжаются.
2. **Факт и restart.** Отправить `Меня зовут Аня`, дождаться завершённого ответа. Закрыть приложение штатно и запустить снова; спросить имя. Затем `Меня зовут Лена` и сразу вопрос об имени: актуальным должно быть новое значение. Старая реплика не должна побеждать исправленный структурированный факт.
3. **Границы памяти.** Временная роль, цитата чужого утверждения и выдуманный моделью факт не переписывают профиль. MVP распознаёт конечный набор явных формулировок из [Memory §9](engine/MEMORY_ENGINE.md#9-p15-a02-явные-знания-и-простой-recall); произвольная фраза не обязательно становится структурированным фактом.
4. **Игра после restart.** Завершить реальную игру, перезапустить и спросить про игру с курсором. Ответ должен учитывать сохранённый допустимый исход, не обещать несостоявшееся участие пользователя и не подменять физическое событие.
5. **Постепенная адаптация.** Одно `Мне нравится игра с курсором` не меняет резко характер. Разнесённые во времени подтверждённые предпочтения накапливаются с пятиминутным gate; после restart сохраняются. Положительный/отрицательный опыт слегка меняет вероятность самостоятельной допустимой игры, не гарантирует конкретный случайный исход и не отменяет quiet/sleep/другие ограничения.
6. **AI-инициатива и ответ.** Сетевые события требуют включённого флага, доступной памяти, подходящего причинного события игры/SocialBid и пройденных локальных gates. Отдельных лимитов event-запросов и пятиминутной задержки после старта нет; admission локальных занятий сохраняет собственные ограничения по [Autonomy](engine/AUTONOMY_ENGINE.md). После показанной AI-фразы ответить `почему?`: ближайший принятый вопрос в пределах 60 секунд получает эту фразу как контекст. Старые инициативы после restart повторно не отправляются.
7. **Ненавязчивость и сеть.** Quiet, меню, сон и приоритетный ввод не допускают фоновой AI-речи. Новое сообщение пользователя отменяет фоновый запрос. Остановка backend, timeout/quota и поздний ответ не возобновляют старую игру, не возвращают удалённую память и не мешают локальным действиям.
8. **Пределы.** Записать CPU/RAM, задержку ответа и фактический расход тестовой сессии. Локальных квот запросов нет; single-flight, deadline/cancellation и отсутствие автоматических повторов сохраняются. При ошибке внешней квоты/429 следующий ручной запрос доступен после завершения предыдущего вызова; отдельной клиентской блокировки по retryAfterMs нет. Ошибка не удаляет последний ответ персонажа; политика — [AI Provider](engine/AI_PROVIDER_CONTRACT.md).

## Состояние и очистка памяти

В существующем чате открыть «Память»: статус различает initializing/persistent/volatile, «О вас» показывает пять разрешённых фактов после успешного чтения. Сохранить также предпочтения прогулок/инициатив: они не вытесняют имя, обращение, тему, стиль ответа и отношение к курсорной игре. Ошибка чтения не изображается пустой памятью. «Как исправить» показывает точную поддерживаемую фразу; пользователь отправляет её сам и обновляет список. Ответ модели не является подтверждением записи.

Проверить раскрытие/сворачивание и доступность кнопок при малом окне. «Новый диалог» не удаляет память. «Очистить всю локальную память» сначала показывает последствия; отмена/закрытие до подтверждения ничего не отправляет. Подтверждение удаляет переписку, факты, эпизоды, карточки, summary, тему/бытовую гипотезу и сбрасывает приобретённое состояние; настройки, внешность и авторская личность сохраняются. Повторный клик не создаёт вторую команду. Успех показывается только по `cleared`; busy/ошибка/неизвестный исход сохраняют честный статус, повтор неизвестного исхода использует прежнюю identity. Закрытие после отправки не отменяет принятую команду.

Во время чтения/очистки выполнить новый диалог/reload: поздние данные и старые формы не возвращаются; после своего успешного reset список обновляется, карточки/summary сохраняют безопасные сценарии согласия. Проверить недоступное хранилище: volatile не обещает удаления durable данных. Очистка локальна и не удаляет уже переданное backend/AI-провайдеру. Контракт — [Memory §6](engine/MEMORY_ENGINE.md#6-полный-reset-и-защита-от-поздних-записей). Ручной Windows-прогон и native clicks отмечать отдельно; DOM-проверки их не заменяют.

Для каждого дефекта записать commit/окружение, шаги, ожидаемое/фактическое поведение и приложить безопасный фрагмент лога без секретов. Не отмечать непроверенные сценарии как пройденные.
