# Сценарии поведения Wisp

Каталог наблюдаемых результатов для реализации и приёмки. Владение, формулы, приоритеты, DTO и fallback определяют [engine contracts](../engine/README.md); сценарии не вводят собственных правил. Сквозная память/сеть проверяются по [Windows checklist](../WINDOWS_MVP_CHECKLIST.md).

## Отдых и сон

Правила: [Character](../engine/CHARACTER_ENGINE.md), [Activity](../engine/ACTIVITY_ENGINE.md), [Animation](../engine/ANIMATION_ENGINE.md).

- При допустимом условии сна персонаж начинает один согласованный цикл сна; отдых и потребность в комфорте сами по себе не означают сон.
- Quiet подавляет навязчивость, сохраняя разрешённое спокойное поведение.
- Допустимое пробуждение проходит Character gate, после чего начинается визуальный wake.
- Drag отменяет активное занятие; физика и отображение следуют общему lifecycle.
- Отсутствие подходящего занятия или клипа приводит к контрактному fallback без второго владельца состояния.

## Исследование и спокойное присутствие

Правила: [Autonomy](../engine/AUTONOMY_ENGINE.md), [Activity](../engine/ACTIVITY_ENGINE.md), [Perception](../engine/PERCEPTION_ENGINE.md), [Motion](../engine/MOTION_ENGINE.md).

- Персонаж чередует idle и допустимое исследование, учитывая состояние и историю повторов.
- Wander может исполняться цепочкой Explore; энергичный вариант Zoomies выбирается только при совместимом разрешённом намерении.
- При отсутствии подходящей среды или цели персонаж остаётся в безопасном состоянии; геометрия не выдумывается.
- Cooldown и история исключают навязчивые повторы по контракту, не создавая отдельного планировщика.
- Drag, падение и потеря опоры прерывают маршрут; Motion сохраняет единственное владение позицией.

## Ввод и игра

Правила: [Behavior Intents](../engine/BEHAVIOR_INTENTS.md), [Activity](../engine/ACTIVITY_ENGINE.md), [Motion](../engine/MOTION_ENGINE.md), [Perception](../engine/PERCEPTION_ENGINE.md).

- Click и pet проходят общую обработку; подтверждённый результат не умножается из-за повторных pointer events или кадров.
- Drag/release передают и возвращают управление позицией по контракту; stale/foreign input не меняет физику.
- Взгляд следует разрешённым observations и не запускает занятие самостоятельно; несовместимый pupil layer допускает visual no-op.
- Игра использует свежую достижимую цель и заканчивается реальным caught/missed/lost_target/cancelled. Речь и анимация соответствуют исходу, завершённая игра не возобновляется от позднего события.
- Нет свежего сигнала или подходящего занятия — нет новой игры; отсутствие специального клипа не меняет её semantic outcome.

## Общение и инициатива

Правила: [Autonomy](../engine/AUTONOMY_ENGINE.md), [AI Provider](../engine/AI_PROVIDER_CONTRACT.md), [AI Events](../../../docs/contracts/AI_EVENTS_CONTRACT.md).

- Локальный невербальный SocialBid возможен без provider; отсутствие допустимого bid оставляет безопасное локальное поведение.
- Quiet, сон и текущие gates подавляют недопустимую инициативу; проигнорированное обращение не создаёт бесконечного повторения.
- Сообщение пользователя проходит общий dialogue flow. AI-предложение проходит локальное admission и не запускает Activity напрямую.
- Недоступность provider сохраняет локальную жизнь; ошибка или неизвестное предложение обрабатывается контрактным fallback.
- На совместимом явно включённом v3 backend речь по игре/SocialBid подчиняется causal gates и приоритету пользователя. Ответ на инициативу получает только разрешённый кратковременный контекст; сеть не управляет физическим lifecycle.
