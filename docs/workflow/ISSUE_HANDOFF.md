# Шаблоны менеджера

Справочник для `project-manager`: читать нужный раздел только перед созданием Issue, выдачей или закрытием спринта. Полномочия и маршрутизация — в [инструкции роли](../../.agents/agents/project-manager/agent.md), инварианты/verification — в [AGENTS.md](../../AGENTS.md).

## Создание Issue

- Сначала проверить дубли и readiness. Title: `[<Task ID>] <один конкретный результат>`, без названия роли/статуса. Task ID после публикации не менять и не переиспользовать.
- Ровно один label `owner:*`; существующие `phase:*`, `track:*`, `area:*`, `needs:architect` — по факту. Новые labels без необходимости не создавать. `documentation` — только для текста, не для типов/контрактов в коде.
- Assignee оставить пустым. Добавить Issue в Project и проверить Status/Priority: `Ready` после readiness, `Blocked` с конкретной причиной при зависимости, `In progress` только при начале работы.
- Тело — до 30–50 строк, до 3–5 ключевых файлов (не добирать список искусственно). Task ID/phase/owner и общие правила AGENTS в теле не повторять.

```markdown
## Цель и Scope
<1–3 предложения: результат, ключевые файлы/модули, ссылки на нужные разделы contracts и связанный architect result.>

## Критерии приёмки
- [ ] <Проверяемое поведение/артефакт>
- [ ] <Краевой случай/сохранённый инвариант>

## Ограничения и Out of Scope
- <Только специфические для задачи ограничения>
- <Явные зависимости; что не входит в slice>

## Verification
<Gate из §11 AGENTS по роли и типу изменений>
```

Одна фича — один законченный vertical slice; связанные методы/DTO не разбивать на отдельные tickets без причины. Для architect-задачи реализация логики/UI вне scope.

## Batch handoff

На каждую из 2–4 задач: `[Task ID] Title`, scope в 1–2 предложениях, ключевые файлы, нужные разделы contracts и `Контекст: текущий чат | новый чат` с краткой причиной. Затем два промпта без повторения полного текста Issue/AGENTS.

**Исполнитель:**

```text
Ты агент <owner-role>. Прочитай .agents/agents/<owner-role>/agent.md, если её ещё нет в контексте. Выполни <Task ID> по актуальной Issue <полный URL>, соблюдая AGENTS.md, scope и связанные architect decisions. Контекст: <целевые файлы и разделы>. Передай результат в reviewer.
```

**Reviewer:**

```text
Ты агент reviewer. Прочитай .agents/agents/reviewer/agent.md, если её ещё нет в контексте. Независимо проверь <Task ID> по актуальной Issue <полный URL> и фактическому diff. Выполни gate для типа изменений из AGENTS.md и верни REVIEW RESULT.
```

## Закрытие

После завершения/Approved и task-scoped коммита: закрыть Issue, проверить фактический `Done` в Project и оставить короткий receipt. Без проверки не заявлять об изменении статуса.

```markdown
## Result — <YYYY-MM-DD>
- Commit: <hash>
- Completion signal: <Approved | Approved (with fast-fixes) | готово>
- Status: Done
```
