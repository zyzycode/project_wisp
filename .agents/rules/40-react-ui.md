# 40-react-ui.md — Стандарты разработки пользовательского интерфейса на React

Правила построения визуального слоя и компонентов компаньона в Renderer-процессе.

---

## 1. Размер и ответственность компонентов
- Компоненты должны быть небольшими, сфокусированными и решать одну визуальную задачу.
- Рекомендуемый размер компонента — до 150 строк кода. Если компонент разрастается, выносите подкомпоненты (например, строку сообщения, аватар, кнопку действия).
- Запрещены «гигантские» монолитные компоненты (Giant Components), объединяющие логику окна, чата и анимаций в одном файле.

---

## 2. Изоляция бизнес-логики
- Компоненты React не вычисляют логику персонажа и не принимают решений об изменении его настроения или маршрута движения.
- Компоненты React и Render Engine adapters не принимают behavior decisions и не знают raw provider DTO.
- Renderer отображает только presentation-ready state/props через typed boundary.
- Вся логика внутри компонентов ограничивается **View-логикой**:
  - Анимация появления всплывающего окна (CSS-транзишены).
  - Управление локальным фокусом в поле ввода текста.
  - Состояние сворачивания/разворачивания списка сообщений.
  - Передача событий ввода пользователя в `window.wispAPI`.

---

## 3. Использование React Hooks
- Используйте стандартные хуки (`useState`, `useEffect`, `useCallback`, `useMemo`) осознанно, избегая лишних ререндеров и бесконечных циклов.
- В `useEffect` обязательно объявляйте полные массивы зависимостей и функции очистки (cleanup functions) при подписке на события IPC:
  ```typescript
  useEffect(() => {
    const unsubscribe = window.wispAPI.onCharacterStateChanged((newState) => {
      setLocalState(newState);
    });
    return () => {
      unsubscribe();
    };
  }, []);
  ```

---

## 4. Управление состоянием (State Management)
- **Локальный UI state (`useState`):** Значение в поле ввода, статус наведения курсора, открыто ли модальное окно.
- **Глобальный UI state (Zustand):** Активная тема оформления, текущие видимые координаты окна, статус отображения чата.
- Не выносите в глобальный стейт данные, которые нужны только одному локальному компоненту.

---

## 5. Производительность рендеринга и прозрачность
- Учитывайте специфику прозрачного окна Electron (`transparent: true`): избегайте тяжёлых CSS-фильтров (`backdrop-filter: blur()`, сложные тени `box-shadow` на больших площадях), которые могут вызывать падение FPS или дефекты композитинга на GPU.
- Спрайты и анимации должны быть оптимизированы для минимального потребления оперативной памяти и графического процессора.
- Детали sprite sheet нарезки, visual bounds, hitbox, anchor points и scaling должны соответствовать `docs/engine/RENDER_ENGINE.md`, если этот документ уже создан.
- Debug UI по умолчанию показывает только status/counters и не раскрывает private memory facts.
