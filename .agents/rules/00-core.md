# Базовые правила разработки

Применяй их к любой задаче в `project_wisp`; детали конкретного слоя бери только из релевантного rule и назначенной Issue.

## Источники и scope

- Исполнимый scope, acceptance criteria и out of scope задаёт назначенная GitHub Issue.
- `AGENTS.md` задаёт ограничения репозитория, `docs/engine/*.md` — стабильные контракты.
- Не реализуй будущие фазы, соседние улучшения и нецелевой рефакторинг.
- Замеченную проблему вне scope опиши в отчёте, не исправляй скрытно.

## Изменения

- Делай минимальный vertical slice и меняй только необходимые файлы.
- Сначала используй существующие типы, порты и утилиты.
- Новая абстракция оправдана изоляцией границы или запланированной сменой реализации.
- Новые npm-зависимости — только через [Dependency Review](../../AGENTS.md#dependency-review).
- Рефакторинг сохраняет поведение и не смешивается с новой функциональностью.

## Постоянные ограничения

- В этом репозитории нет backend/proxy/server, прямых AI SDK и пользовательских AI API-ключей.
- Domain и Application не зависят от ОС; Renderer не получает Node.js API.
- Не скрывай ошибки типизации через `any`, `@ts-ignore` или необоснованные assertions.

## Завершение

- До правок назови затрагиваемые файлы и короткий план.
- Для product code выполни проверки, соответствующие риску; для docs-only проверь ссылки и diff.
- В отчёте укажи scope, изменения, сохранённые границы, проверки и следующий gate.
