# SKILL: electron-security — Безопасность настольного приложения Electron

Руководство по обеспечению безопасности, аудиту уязвимостей и защите среды выполнения Electron.

---

## 1. Главные векторы атак в Electron

При разработке приложений на Electron критически важно предотвратить выполнение произвольного кода (Remote Code Execution, RCE) через скомпрометированный Renderer процесс или небезопасные внешние данные.

---

## 2. Чек-лист безопасности архитектуры

### 2.1. Изоляция процессов и конфигурация окон
- [x] `contextIsolation: true` включено для каждого окна.
- [x] `nodeIntegration: false` строго выключено везде.
- [x] `sandbox: true` включено для веб-контекста.
- [x] `webSecurity: true` включено.
- [x] Отключен протокол `file://` для загрузки удалённых ресурсов.

### 2.2. Защита Preload-скрипта
- [x] Никогда не экспортировать объект `ipcRenderer` целиком через `contextBridge.exposeInMainWorld`.
- [x] Экспортировать только функции-обёртки с явной валидацией входных параметров.
- [x] Предотвращать утечку прототипов Node.js объектов.

### 2.3. Межпроцессное взаимодействие (IPC)
- [x] Обработчики `ipcMain.handle` и `ipcMain.on` никогда не должны слепо доверять данным из `event.sender`.
- [x] Входящие DTO должны валидироваться (проверка типов, диапазонов чисел, длины строк).
- [x] Запрещено передавать команды для выполнения в shell через IPC.

### 2.4. Внешние ссылки и навигация
- [x] Блокировать событие `will-navigate` для неизвестных доменов.
- [x] Перехватывать создание новых окон `setWindowOpenHandler`.
- [x] Валидировать протоколы перед вызовом `shell.openExternal` (разрешать только `https:` / `http:` после проверки).

### 2.5. Файловая система и SQLite
- [x] Доступ к `better-sqlite3` и `fs` разрешён **только в Main-процессе**.
- [x] Пути к файлам базы данных и логов формируются через безопасные системные методы `app.getPath('userData')`, запрещена конкатенация непроверенных пользовательских строк в пути.
- [x] Использование параметризованных SQL-запросов (`stmt.run(params)`) для исключения SQL-инъекций.
