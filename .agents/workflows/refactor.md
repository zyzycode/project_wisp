# refactor.md — Регламент проведения рефакторинга

Регламент безопасного улучшения структуры кода без изменения функционального поведения.

---

## 1. Подготовка и фиксация поведения
1. Убедись, что для рефакторимого модуля существуют исчерпывающие тесты.
2. Если тестов недостаточно — **сначала напиши тесты на текущее поведение**, запусти их и убедись в их успешности.
3. Категорически запрещено совмещать добавление новых фичей с рефакторингом в одном шаге.
4. Если рефакторинг меняет границы слоёв, IPC, порты или platform contracts — сначала получи решение `architect`.

---

## 2. Итеративный процесс
1. Проводи изменения малыми, контролируемыми шагами (выделение метода, переименование, разделение модуля, извлечение интерфейса).
2. После каждого микро-шага запускай тесты и проверку типов:
   ```bash
   npm run typecheck && npm test
   ```
3. Проверяй соблюдение архитектурных границ:
   - Не появились ли циклические импорты?
   - Не нарушилось ли направление зависимостей?

---

## 3. Финализация
1. Запусти полный цикл проверок: `typecheck`, `lint`, `test`.
2. Убедись в отсутствии неиспользуемых импортов и устаревших комментариев.
3. Сообщи о результатах рефакторинга и улучшении метрик (уменьшение сложности, разделение ответственности).
