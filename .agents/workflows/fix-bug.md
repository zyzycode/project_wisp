# fix-bug.md — Регламент исправления ошибок (Bugfix)

Регламент для локализации и устранения дефектов в Project Wisp. Bugfix выполняется по конкретному `Task ID` или fix-gate из [.agents/tasks/README.md](../tasks/README.md), если дефект найден в рамках backlog workflow.

---

## 1. Воспроизведение и локализация
1. Подтверди `Task ID`, fix-gate, owner-agent и confirmed finding от `reviewer`.
2. Проанализируй стек вызовов ошибки или описание некорректного поведения.
3. Локализуй точное место возникновения сбоя (процесс: Main, Preload или Renderer; модуль; функция).
4. Определи фундаментальную первопричину (Root Cause), а не маскируй симптомы.
5. Если дефект требует изменения public contracts, `docs/engine/*`, IPC, ports или границ слоёв, верни задачу Project Manager-у с recommended gate `architect`.

---

## 2. Разработка минимального фикса
- **Строгий запрет:** Категорически запрещено переписывать модуль целиком или менять соседний код, не имеющий отношения к ошибке.
- Внеси точечное изменение, устраняющее сбой.
- Проверь, чтобы фикс не ломал существующие контракты и обратную совместимость.
- Не меняй статусы, зависимости, owner-agent или порядок задач в shared backlog.
- Не добавляй backend/proxy/server implementation, dev gateway, прямые LLM SDK, пользовательские AI API-ключи или server auth/billing.

---

## 3. Регрессионное тестирование
1. Напиши юнит-тест (Regression Test), который воспроизводит условие сбоя до фикса и успешно проходит после применения фикса.
2. Запусти полный набор тестов: `npm test`.
3. Запусти `npm run typecheck` и `npm run lint`.
4. Если затронуты сборка, Electron config или packaging, запусти `npm run build`.

---

## 4. Итоговый отчёт
Укажи в ответе:
- `Task ID` и fix-gate.
- Первопричину дефекта.
- Описание точечного исправления.
- Ссылки на изменённые файлы и добавленный тест.
- Результаты проверок.
- Recommended next gate: `reviewer`, `architect`, `done` или `blocked`.
